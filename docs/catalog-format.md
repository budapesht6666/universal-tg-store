# Формат каталога

Каталог — один JSON-файл: настройки магазина, характеристики товаров, категории и товары. Этот же формат используется для импорта и экспорта в админке.

- Пример: [`catalog/example.catalog.json`](../catalog/example.catalog.json) — демо-магазин, им заполняется пустая база.
- JSON Schema: [`catalog/catalog.schema.json`](../catalog/catalog.schema.json). Если в начале файла указано `"$schema": "./catalog.schema.json"`, VS Code подсказывает поля и подчёркивает ошибки прямо при вводе.
- Источник правды — zod-схемы в [`packages/schema`](../packages/schema/src). JSON Schema генерируется из них командой `pnpm schema:gen`, руками её не правим.

## Общие правила

| Что                 | Правило                                                                                                    |
| ------------------- | ---------------------------------------------------------------------------------------------------------- |
| Деньги              | Целое число в **минорных единицах** (копейках): `199000` = 1 990 ₽. Дробные суммы — ошибка                 |
| `id`                | Латиница в нижнем регистре, цифры и дефис: `tee-basic`. До 64 символов, уникален в своём списке            |
| Ключи характеристик | Латиница и цифры, начинается с маленькой буквы: `material`, `maxWeight`                                    |
| Даты                | ISO 8601: `2026-11-14T10:00:00Z`                                                                           |
| Картинки            | `{ "url": "https://…", "alt": "…" }`; `url` — ссылка `https://` или путь к загруженному файлу `/uploads/…` |
| Неизвестные поля    | Ошибка. Так опечатка (`"prise"` вместо `"price"`) не потеряется молча                                      |

Поля со значением по умолчанию можно не писать — при разборе они подставятся.

## Верхний уровень

```jsonc
{
  "$schema": "./catalog.schema.json", // необязательно, для подсказок в редакторе
  "version": 1,                        // версия формата, обязательно
  "settings": { … },
  "attributes": [ … ],                 // характеристики товаров
  "categories": [ … ],
  "products": [ … ]
}
```

## `settings` — настройки магазина

Обязательно только `settings.shop.name`, остальное имеет значения по умолчанию.

```jsonc
"settings": {
  "shop": {
    "name": "Universal Store",
    "description": "",
    "greeting": "Привет! …",   // ответ бота на /start
    "locale": "ru-RU",         // формат чисел и дат
    "currency": "RUB"          // ISO 4217
  },
  "features": {                // фичи каталога, по умолчанию все включены
    "categories": true, "search": true, "sort": true, "gallery": true,
    "discounts": true, "badges": true, "stock": true
  },
  "catalog": { "defaultView": "grid" },       // grid — плитка, list — список
  "checkout": {
    "fields": [ … ],                          // поля оформления, см. ниже
    "phoneFromTelegramOnly": false,           // номер только из Telegram, ручной ввод запрещён
    "maxQtyPerItem": 100                      // максимум штук одного товара
  },
  "orders": { "customerCanCancel": true },    // покупатель сам отменяет заказ в статусе «Оформлен»
  "delivery": {
    "assignment": "manual",                   // manual — менеджер выбирает курьера; pool — курьеры берут сами
    "shopPhone": "+7 495 000-00-00"           // сюда звонит покупатель, если курьер скрыл номер
  }
}
```

Выключенная фича пропадает из магазина, данные товаров при этом не теряются. Сколько штук можно положить в корзину: `min(maxQtyPerItem, stock)`; если `features.stock` выключен или `stock: null` — только `maxQtyPerItem`. Сервер проверяет это тоже.

### Поля оформления (`checkout.fields`)

Список описаний полей (FieldDefinition, см. ниже). По умолчанию: имя, телефон, адрес, комментарий. **Должно быть ровно одно обязательное поле типа `phone`** — без телефона курьер не сможет передать заказ. Телефон хранится в виде `+79991234567`, российские `8…` приводятся к `+7…`.

## `attributes` — характеристики товаров

Свои поля товара без правки кода: материал, плотность, объём… Описание — FieldDefinition плюс два флага показа:

```jsonc
{
  "key": "density",
  "label": "Плотность",
  "type": "number",
  "integer": true,
  "min": 40,
  "max": 600,
  "unit": "г/м²",
  "hint": "От 40 до 600",
  "required": false,
  "showInSpecs": true, // в блоке «Характеристики» на странице товара (по умолчанию true)
  "showInCard": false // в карточке каталога (по умолчанию false)
}
```

Значения хранятся в товаре: `"attributes": { "density": 180 }`. Они проверяются по описанию: неизвестный ключ, значение не того типа, выход за `min`/`max`, вариант не из списка — ошибка с путём до значения.

## FieldDefinition — описание поля

Общие свойства: `key`, `label`, `hint`, `placeholder`, `required` (по умолчанию `false`).

| `type`        | Значение              | Дополнительные свойства                        |
| ------------- | --------------------- | ---------------------------------------------- |
| `text`        | строка                | `minLength`, `maxLength` (по умолчанию до 500) |
| `textarea`    | строка                | `maxLength`                                    |
| `markdown`    | строка с разметкой    | `maxLength`                                    |
| `number`      | число                 | `min`, `max`, `integer`, `unit`                |
| `money`       | целое в копейках      | `min`, `max`                                   |
| `boolean`     | `true` / `false`      | —                                              |
| `select`      | один из `options`     | `options` (список строк)                       |
| `multiselect` | список из `options`   | `options`, `maxItems`                          |
| `url`         | ссылка `https://…`    | —                                              |
| `image`       | `{ url, alt }`        | —                                              |
| `images`      | список `{ url, alt }` | `maxItems`                                     |
| `tags`        | список строк          | `maxItems`                                     |
| `date`        | `ГГГГ-ММ-ДД`          | —                                              |
| `color`       | `#RRGGBB`             | —                                              |
| `phone`       | телефон               | —                                              |

Из одного описания строятся три вещи: проверка значения (одна и та же на сервере и в админке — `buildZodSchema`), поле формы в админке и поле оформления в магазине. Пустая строка из формы считается «не заполнено».

## `categories`

```json
{ "id": "wear", "title": "Одежда", "sort": 10 }
```

`sort` — порядок показа (по возрастанию), по умолчанию 0.

## `products`

```jsonc
{
  "id": "tee-base", // обязательно
  "sku": "TB-001", // артикул, уникален
  "title": "Футболка «Base»", // обязательно, до 120 символов
  "shortDescription": "…", // для карточки каталога, до 160 символов
  "description": "…", // Markdown, HTML не поддерживается
  "price": 199000, // обязательно, в копейках
  "compareAtPrice": 249000, // старая цена, должна быть больше price
  "images": [{ "url": "https://…", "alt": "…" }],
  "categoryIds": ["wear"], // каждая категория должна существовать
  "badges": ["Хит"], // до 5 меток, до 24 символов
  "stock": 12, // остаток; null — без учёта остатков (по умолчанию)
  "isActive": true, // false — скрыт из магазина
  "sort": 0,
  "attributes": { "material": "Хлопок", "density": 180 },
  "createdAt": "2026-10-20T09:00:00Z",
  "updatedAt": "2026-10-20T09:00:00Z"
}
```

## Проверка и ошибки

`parseCatalog(json)` из `@store/schema` проверяет файл целиком и возвращает либо нормализованный каталог, либо **все** ошибки сразу, с путём до места:

```
products[3].price: Сумма не может быть отрицательной
products[1]: Неизвестное поле «prise» — проверьте написание
products[0].categoryIds[1]: Нет категории «shoes»
products[2].sku: Артикул «TB-001» уже есть (повтор, первый — №1)
products[0].attributes.density: Не больше 600
settings.checkout.fields: Нужно ровно одно обязательное поле типа phone — без телефона курьер не сможет передать заказ
```

Импорт в админке сначала показывает такой отчёт (dry-run) и только потом применяет изменения — с ошибками база не меняется.

## Версии формата

`version` — номер формата. Если формат изменится, шаблон получит версию 2 и миграцию: старые файлы будут обновляться при импорте автоматически (`MIGRATIONS` в `packages/schema/src/parse.ts`). Файл новее, чем понимает шаблон, не импортируется — будет понятная ошибка.

## Как расширить формат

1. Добавьте поле в zod-схему в `packages/schema/src/catalog.ts` (со значением по умолчанию — тогда старые файлы останутся валидными).
2. Новая фича каталога — новый флаг в `FeaturesSchema` (инвариант проекта).
3. `pnpm schema:gen` — обновить JSON Schema; тест сверяет её с zod-схемой.
4. Обновите этот документ и пример каталога.

Для своих полей товара код не нужен — это `attributes`.
