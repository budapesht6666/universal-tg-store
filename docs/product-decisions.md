# Продуктовые решения

Согласовано на этапе дизайна (ноябрь 2026). Макеты — в [`design/`](../design/README.md). Менять эти правила — только осознанно, вместе со схемами в `packages/schema`.

## Оформление

- Поля по умолчанию: имя, телефон, адрес, комментарий. Самовывоза нет. Набор полей настраивается (`settings.checkout.fields`).
- **Телефон обязателен** — курьер должен дозвониться. Подпись «Курьер позвонит перед доставкой», ошибка «Без телефона курьер не сможет передать заказ».
- Кнопка «Из Telegram» (`requestContact`) подставляет подтверждённый номер. Настройка «Телефон только из Telegram» запрещает ручной ввод (по умолчанию выключена).
- Лимит штук одного товара — настройка, по умолчанию 100. Фактический максимум = min(лимит, остаток). Сервер проверяет тоже.

## Статусы заказа

Один словарь для магазина, админки и бота (в коде — единственный источник в `packages/schema`):

```
Оформлен → Собираем → Курьер в пути → Доставлен
    └───────────┴────────────┴──────► Отменён
```

- «Доставлен» и «Отменён» — конечные. Допустимые переходы проверяет сервер.
- Экран заказа у покупателя: крупно — текущее состояние и чего ждать, полоса прогресса, история шагов. Об изменениях покупатель узнаёт сообщением бота с deep link на заказ (`startapp=o_<id>`); если вошёл мимо `/start` — просим `requestWriteAccess`.

## Отмена

| Кто        | Когда                       | Как                                                                                                                                                                                    |
| ---------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Покупатель | «Оформлен»                  | Сам, с подтверждением. Остатки возвращаются сразу. Отключается настройкой «Покупатель может отменить заказ сам» (по умолчанию вкл.)                                                    |
| Покупатель | «Собираем», «Курьер в пути» | Только «Попросить отменить» — просьба уходит менеджеру через бота                                                                                                                      |
| Менеджер   | До «Доставлен»              | Причина обязательна (нет в наличии / не дозвонились / покупатель попросил / другое), галочка «Вернуть товары на склад» (по умолчанию вкл.). Причина уходит покупателю и видна в заказе |

- Гонка «покупатель отменяет, менеджер принимает»: условный `UPDATE ... WHERE status = 'new'`; проигравший получает понятное сообщение.
- Возврат остатков — в той же транзакции, что и смена статуса, ровно один раз.
- История хранит, кто и почему отменил. Отмена доставленного заказа = возврат, пока не делаем. С онлайн-оплатой отмена оплаченного заказа должна запускать возврат денег (точка расширения `PaymentProvider`).

## Команда и курьеры

- Роли: **владелец**, **менеджер**, **курьер**; у одного человека может быть несколько. `ADMIN_IDS` из `.env` нужен только для первого владельца, дальше роли хранятся в БД.
- Добавление — раздел «Команда»: одноразовая ссылка-приглашение `t.me/<bot>?start=inv_<token>` на 24 часа, бот просит поделиться номером. Выключенный или удалённый участник сразу теряет доступ.
- **Курьер работает в боте**: карточка заказа с кнопками «Забрал, еду» (→ «Курьер в пути»), «Доставлен», «Не получилось» с причиной (→ заказ возвращается менеджеру), «Не могу взять». Экран «Мои доставки» в Mini App — позже.
- Раздача заказов — настройка: **вручную** (по умолчанию, менеджер выбирает курьера) или **курьеры берут сами** (первый нажавший «Беру», условный `UPDATE`). Если активный курьер один — назначается автоматически.
- Назначение курьера статус не меняет: «Курьер в пути» ставит сам курьер, когда забрал заказ.
- Покупатель видит имя курьера и пишет ему через бота. Номер курьера показывается, только если курьер сам это разрешил; иначе звонок идёт на «Телефон магазина» из настроек.
- Персональные данные: адрес и телефон покупателя курьер видит, только пока заказ у него; после доставки они скрываются из его чата. В режиме «берут сами» до взятия заказа — без точного адреса и телефона.

## Связь

- Покупатель ↔ менеджер и покупатель ↔ курьер — через бота (relay): сообщение уходит адресату, ответ приходит обратно, переписка видна в заказе в админке.

## Оформление интерфейса

- Тема следует Telegram и устройству. Светлая: фон страницы `#F2F2F7` (`secondary_bg_color`), карточки и поля белые (`bg_color`). Админка: фон `#F4F4F5`, карточки белые.
- Каталог: плитка в две колонки по умолчанию (настраивается в админке), покупатель может переключить на список. В шапке корзина — иконка со счётчиком, без суммы.
- Шаблон без бренда: всё оформление — через токены и настройки, бренд добавляется в производном проекте.
